NAMP → CRMS Integration Guide National Agricultural Mechanization Program · Bank of Agriculture · Heifer Nigeria

1. What This Guide Covers

The NAMP applicant portal collects all loan application data from shortlisted applicants across three categories: Mechanisation Company, Youth Entrepreneur, and Woman Entrepreneur. When an applicant completes all requirements and clicks Submit to CRMS, the NAMP API calls your webhook with a single JSON payload containing the full loan file — applicant details, credit profile, guarantors, collateral, financial statements (company only), equipment cart, and uploaded supporting documents with their AWS S3 storage locations.

This document tells you exactly what to expect, what to return, and how to handle every field in the payload.

Summary — what you need to build A single POST endpoint that: accepts a JSON body as described below, creates the loan application in CRMS, and returns a JSON object containing applicationId and applicationNumber.

4. Endpoint & Authentication

4.1 Your Webhook Endpoint

The CRMS team provides one URL. NAMP stores it in appsettings.json under Crms:WebhookUrl.

PropertyValue
MethodPOST
URLProvided by CRMS team — e.g. https://crms.yourbank.ng/api/namp/applications
Content-Typeapplication/json; charset=utf-8
Auth headerX-Api-Key: {ApiKey}

4.2 API Key

The CRMS team generates an API key and shares it with the NAMP technical team. NAMP stores it in appsettings.json → Crms:ApiKey and sends it on every call as the X-Api-Key header. Validate it server-side and return 401 if it is missing or incorrect.

5. Request Format

All field names are camelCase. All monetary values are Nigerian Naira (NGN) as raw decimal numbers — no commas, no currency symbols. Financial statement figures follow the same convention (confirm with NAMP team if NGN '000 or full NGN is expected for your system). Dates are ISO 8601 strings: "yyyy-MM-dd" for dates, "O" (round-trip) format for timestamps.

6. Expected Response

On success return 200 OK with:

{
  "applicationId":     "crms-internal-uuid-or-id",
  "applicationNumber": "NAMP-2026-XXXXXXXX"
}

Both values are stored in the NAMP database and displayed to the admin and applicant.

  • applicationId — your internal unique identifier for the loan application (can be a UUID, integer ID, or reference string).
  • applicationNumber — the human-readable reference the loan officer and applicant will use (e.g. NAMP-2026-ABC12345).

7. Error Handling

HTTP StatusMeaningNAMP Behaviour
200 Application created successfully Stores applicationId + applicationNumber, marks CRMS as submitted, locks equity snapshot.
4xx Validation or business rule failure Returns the error to the applicant screen. Applicant can retry. Application is not marked as submitted.
401 Invalid or missing API key Same as 4xx — error shown, not marked submitted.
5xx / timeout Server error on CRMS side Same as 4xx — applicant sees "CRMS service unavailable" and can retry.
Important — do not return 200 on failure If you cannot create the application, return a 4xx or 5xx status. Returning 200 with an empty body or an error message will cause NAMP to store blank CRMS references and mark the application as submitted — the applicant will not be able to re-submit.

8. Idempotency

NAMP is idempotent on its side — once a successful response is received, the endpoint will not call your webhook again for the same application; it returns the stored CRMS references immediately.

However, network failures or retries mean you may receive the same applicationReference more than once. We recommend treating applicationReference as a unique key and returning the existing CRMS IDs if the application already exists rather than creating a duplicate.

Deduplication key: applicationReference — a 32-character hex string (UUID without hyphens). It is unique per NAMP application and never changes.

14. documents[] — Uploaded Document Object

Each item represents one uploaded Phase 2 document. The CRMS team can retrieve the actual file from AWS S3 using the s3BucketName + s3Key pair: GetObject(bucket, key). No presigned URL is included — CRMS must use its own AWS credentials (or an IAM role) with s3:GetObject permission on the NAMP bucket.

S3 access note Bucket: bankofagriculturetpdirectdocs (AWS region: eu-west-1). The CRMS IAM role requires s3:GetObject on arn:aws:s3:::bankofagriculturetpdirectdocs/phase2-docs/*. Keys follow the pattern: phase2-docs/{applicationId}/{documentType}/{timestamp}_{filename}.
